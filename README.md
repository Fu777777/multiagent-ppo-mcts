# 多智能体强化学习策略博弈：PPO 自对弈 + MCTS（简化 Connect-4）

用 PyTorch 从零实现：一个策略-价值网络通过 **PPO 自对弈**（双方共享参数）学习下简化版四子棋，再用 **MCTS（PUCT）** 结合网络先验与价值做搜索增强；最后用自动化对战脚本统计 随机 / 纯 MCTS / PPO / PPO+MCTS 两两胜率。全部代码约 360 行。

## 1. 设计

- **游戏**（`mappo/game.py`）：5 行 × 6 列、连 4 子获胜、棋子下落。状态空间比标准 6×7 小，CPU 几分钟能训练。
- **多智能体 & 参数共享**：观测总是“当前要走的一方”视角（2 个平面：己方子、对方子，共 60 维）。同一个网络同时扮演先手和后手，两个玩家的经验都进同一个 batch。这是零和双人博弈里最简单的多智能体设定（自对弈）。
- **网络**（`mappo/net.py`）：60→256→256 共享主干，策略头输出 6 列 logits（满列被掩码），价值头 tanh 输出当前方的胜负期望 ∈ [-1,1]。
- **PPO**（`mappo/ppo.py`）：每轮自对弈 64 局；终局时胜方每一步回报 +1、负方 −1、平局 0，按该玩家自己的步数折扣 γ=0.99；优势 A = G − V(s) 并标准化；裁剪 ε=0.2、4 个 epoch、价值系数 0.5、熵系数 0.01。
- **MCTS**（`mappo/mcts.py`）：PUCT 选择 `Q + c·P·√N_parent/(1+N)`，c=1.5。
  - PPO+MCTS：P 用网络先验，叶子价值用网络价值头（AlphaZero 式，不做 rollout）。
  - 纯 MCTS 基线：均匀先验 + 随机 rollout 到终局估值。
  - 价值按“走到该节点的一方”存储，回传时逐层取反（负极大值）；最终选访问次数最多的列。
- **对战测试**（`arena.py`）：4 个智能体两两对战。确定性策略互下只会产生 2 盘不同的棋，所以每对棋局先**随机走 2 步作为开局**，同一开局双方各执先一次；平局记半胜。

## 4. 实际运行结果

环境：Linux 容器、CPU 单线程、Python 3.13、torch 2.14.1+cpu。种子 0。

训练（`logs_train.txt`，1000 轮 × 64 局自对弈，共 185 秒；评估时贪心 PPO 对随机 100 局，`play_match` 默认同样先随机走 2 步开局，种子 0）：

| 轮数 | 价值损失 | 策略熵 | 贪心 PPO vs 随机 100 局 胜/平/负 |
|---|---|---|---|
| 250 | 0.442 | 0.465 | 91/0/9 |
| 500 | 0.548 | 0.292 | 77/9/14 |
| 750 | 0.257 | 0.308 | 78/2/20 |
| 1000 | 0.021 | 0.215 | 85/1/14 |

对战胜率表（`logs_arena.txt`，每对 100 局，MCTS 100 次模拟；行对列的胜率，平局记半胜）：

| 行\列 | 随机 | 纯MCTS(100) | PPO | PPO+MCTS(100) |
|---|---|---|---|---|
| 随机 | - | 0% | 28% | 8% |
| 纯MCTS(100) | 100% | - | 94% | 64% |
| PPO | 72% | 6% | - | 17% |
| PPO+MCTS(100) | 92% | 36% | 83% | - |

模拟次数加到 400（`logs_arena_400.txt`）：

| 行\列 | 随机 | 纯MCTS(400) | PPO | PPO+MCTS(400) |
|---|---|---|---|---|
| 随机 | - | 0% | 27% | 4% |
| 纯MCTS(400) | 100% | - | 96% | 78% |
| PPO | 73% | 4% | - | 6% |
| PPO+MCTS(400) | 96% | 22% | 94% | - |

### 结论（如实）
1. **MCTS 显著增强 PPO**：同一网络加 100 次模拟后对纯 PPO 胜率 83%，400 次时 94%；对随机从 72% 提升到 92%/96%。
2. **但本次训练出的网络还不够强**：纯 MCTS（随机 rollout）仍然胜过 PPO+MCTS（100 次模拟 64%，400 次 78%）。在这么小的棋盘上随机 rollout 已经是不错的价值估计，而网络价值头质量不足。
3. **训练不稳定**：价值损失在 0.02~0.85 之间大幅震荡（见 `logs_train.txt`），熵降到 0.2 左右，说明双方策略趋于确定、对局重复度高。（更正：旧版此处称“训练中对随机 85%、加随机开局后 72~73% 说明泛化差”，但训练内评估同样有 2 步随机开局，差异来自对局种子不同和 100 局的统计噪声，不能据此得出泛化结论。）
4. **定性说明**：这是双人零和博弈中“参数共享的自对弈”，只有一个学习网络，并非 MAPPO 那类多学习体/集中式 critic 的多智能体强化学习；MCTS 只在对战推理时使用，训练中未用搜索结果做蒸馏。

## 5. 面试讲解要点 / 局限与改进
- 为何参数共享：零和对称博弈，视角翻转后双方是同一个问题，样本翻倍、天然自对弈课程。
- 难点：MCTS 中价值的视角与符号（负极大值回传）；终局节点的处理；确定性对战需随机开局才有统计意义。
- 局限：PPO 只用终局回报 → 信用分配粗；纯自对弈易陷入策略循环/模式坍缩；网络是 MLP，没利用棋盘平移不变性。
- 改进：对手池（与历史版本对战）、提高熵系数、用卷积网络；AlphaZero 式用 MCTS 访问分布作为策略目标（搜索→蒸馏）；训练时加入随机开局或 Dirichlet 噪声。
